# QueryDraft UI / 設計判断

SQLを視覚的に組み立て、操作と構文・結果の関係を学ぶ。管理対象の本番DBを必要とせず、ブラウザ内の教材を使う。

## 合意した画面

- FlowDraftと同じくキャンバスを画面の土台にし、機能は下部ナビへ集約する。
- 常設カードはテーブルノードだけに絞り、開始テーブル・結合・条件・SQL・結果・解説は下部ワークベンチで開く。
- 下部ナビ中央の「生成SQL」を主結果として強調する。キャンバスで触った内容を即座にSQLへ変換し、実行後は結果タブへ移る。
- 各テーブルは列一覧とExcel風のカラム名＋先頭3行を個別に切り替える。関係線は保つ。
- 選択と条件はビュー間で共有。列名を押すとSELECT、セルを押すとWHERE。
- 関連テーブルの列を選ぶと、定義済み外部キーの経路からJOINを補完する。
- Mermaid風の表現だが、実装はHTMLノード＋SVG。固定の教材関係を使用し、任意の結合線編集は後続。

## Vaultから反映した考え方

`70 AI/AI Agents/Design Research/DESIGN-PREFERENCES.md`の「主役を一つ」「同義UI・重複情報を避ける」「主操作を動かさない」を採用。重複する左サイドバーと常設の結果カード群を省き、表自体を操作面、生成SQLを主結果にする。

`20 Projects/FlowDraft/FlowDraft 開発秘話 下書き.md`の「設計図と読み方を分ける」を採用。クエリモデル、表示状態、SQL実行を分離し、意味の解説を必要時に開けるようにする。下書きの文章そのものや個人情報は教材へ転用しない。

## 実装境界

- 素のHTML/CSS/JavaScript。React不要。npmはSQLiteの取得と配布用コピー・テストにのみ使用。
- sql.jsをローカル配布し、Web Workerで実行。10秒で打ち切り・エンジン再作成。教材は毎回初期化。
- WHERE値はバインド。識別子・演算子は許可リスト。表示SQLは値を引用したコピー用表現。
- 自由入力SQLはまだ対象外。query_onlyを併用するが、任意SQLのセキュリティ境界とはみなさない。
- SELECTの選択順と論理的な読み方、DBの物理実行順を混同させない。
- JOIN/EXISTS/サブクエリは無条件に同値でないため、初版に切替タブを置かない。
